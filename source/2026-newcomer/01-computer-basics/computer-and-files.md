# 计算机与文件

## 一、计算机

### 1. 硬件与软件

计算机系统由硬件和软件两部分组成，二者相互依存，共同完成计算、存储、交互等所有任务。

我们可以把计算机比作一间独立的实验工作站：硬件是实验台、仪器、存储柜等实体设备，软件是实验方案、操作流程、数据公式等虚拟的部分，二者缺一不可。

#### 1.1 核心硬件及其作用

硬件是计算机中所有有形的物理设备，与实验密切相关的核心硬件有四类：

1. **中央处理器（CPU）**：计算机的“计算大脑”，负责执行所有程序指令、处理运算逻辑。实验中代码运行、数据计算、模型训练的速度，核心取决于 CPU 的性能。
2. **内存（RAM，随机存取存储器）**：计算机的“临时工作台”，用于存放正在运行的程序和正在处理的实验数据。读写速度极快，但断电后数据会全部丢失。实验中同时打开多个工具、处理大容量数据集时，内存不足会导致程序卡顿甚至崩溃。
3. **外存（硬盘 / 固态硬盘）**：计算机的“长期储物柜”，用于持久化存放文件、代码、实验数据集。断电后数据不会丢失，我们的实验代码、报告、原始数据都存储在其中。
4. **输入 / 输出设备**：人机交互的媒介，包括键盘、鼠标、显示器、U 盘、实验外设等。我们通过输入设备下达操作指令，通过输出设备获取实验结果。

```{note}
新手提示：我们常说的“电脑能不能跑这个实验”，主要评估 CPU 性能、内存大小、硬盘存储空间三项核心指标。
```

#### 1.2 软件的分类

软件是运行在硬件之上的程序、数据及相关文档的集合，按照功能可分为两大类：

1. **系统软件**：负责管理计算机本身、为上层软件提供运行基础的软件，最核心的就是操作系统，此外还包括编译器、硬件驱动、系统工具等。它是连接硬件与应用软件的桥梁，普通用户通常不会直接修改系统软件。
2. **应用软件**：为完成特定场景任务开发的软件，比如编写代码用的 VS Code、查资料用的浏览器、处理数据用的表格工具、实验用的仿真软件等。我们做实验安装环境，本质就是在操作系统上部署各类应用软件和开发工具。

#### 1.3 硬件与软件的关系

- 硬件是软件运行的物理载体，硬件性能决定了软件运行的速度上限；
- 软件是硬件功能的实现逻辑，没有软件的硬件只是一堆无法工作的电子元件；
- 所有实验代码、应用程序，最终都要通过操作系统调度硬件资源来执行。

### 2. 核心名词

| 名称 | 用途 |
| --- | --- |
| CPU | 执行计算和控制任务 |
| GPU | 处理图形和大规模并行计算 |
| 内存 | 临时存放正在运行的数据（断电丢失） |
| 硬盘 | 长期保存系统、软件和文件（断电不丢失） |
| 操作系统 | 管理计算机硬件与软件资源，提供人机交互界面，支撑各类应用程序运行（如 Windows、macOS、Linux） |

### 3. 操作系统

操作系统（Operating System，简称 OS）是管理计算机硬件与软件资源的核心程序，是所有软件运行的基础。它相当于计算机的“大管家”：向下调度 CPU、内存、硬盘等硬件，向上为我们使用的浏览器、代码编辑器、实验程序提供运行环境。

最常用的操作系统有三类：

- **Windows 系统**：图形化界面友好，操作直观，多用于日常文档编写、本地代码编写、实验数据初步处理。
- **Mac OS 系统**：苹果电脑专属系统，基于 Unix 内核开发，兼具友好的图形化界面和类 Linux 的命令行环境。既适合日常文档编写、本地代码开发，其终端操作又与实验室 Linux 服务器高度兼容，是从桌面系统过渡到服务器环境的极佳选择。
- **Linux 系统**：以命令行操作为主，稳定性强、资源占用低，是服务器、嵌入式设备、算力节点的主流系统。后续的编程实验、服务器部署、大数据与人工智能相关实验，大多需要在 Linux 环境下完成，是需要重点掌握的环境。

#### 4.1 系统版本

系统版本是同一操作系统的不同迭代发行版，类似于同一本教材的不同修订版本：核心框架不变，但会修复漏洞、新增功能、优化性能，不同版本之间存在一定的兼容性差异。

**版本匹配原则**

安装任何实验工具、依赖库、编译器前，都需要确认该工具支持的系统版本范围：

- 系统版本过低：无法使用新版工具的功能，存在安全漏洞；
- 系统版本过高：部分旧实验工具未适配，会出现兼容报错。

#### 4.2 芯片架构

芯片架构也叫 CPU 架构、指令集架构，是 CPU 的底层设计规范，相当于 CPU 的“母语”。不同架构的 CPU 能识别的机器指令不同，就像说中文和英文的人无法直接交流。软件必须编译成对应架构的指令，才能在该 CPU 上正常运行。这也就是为什么在前文中，不同的芯片架构需要有不同的程序包。常见的芯片架构和注意点如下。

| 架构全称 | 常用别名 | 典型设备 | 安装包标识关键词 |
| --- | --- | --- | --- |
| x86_64 | amd64、x64 | Intel/AMD 芯片的 Windows 电脑、旧款 Intel 芯片 Mac、主流服务器 | x64、x86_64、amd64、Intel |
| ARM64 | aarch64、Apple Silicon | 苹果 M 系列芯片 Mac、嵌入式开发板、ARM 架构服务器 | arm64、aarch64、Apple Silicon |
| RISC-V | riscv64 | 教学开发板、科研嵌入式设备 | riscv64 |

### 5. 软件、程序与进程

我们编写的实验代码、使用的软件，在操作系统中以“程序”和“进程”两种形态存在，二者是完全不同的概念。

#### 5.1 什么是程序

程序是一组有序的计算机指令集合，通常以文件形式存储在外存中，是静态的。比如你编写的 `exp1.c` 源代码、编译后生成的可执行文件、安装好的 VS Code 软件，都属于程序。它安静地存储在文件夹里，不运行就不会占用 CPU 和内存资源。

#### 5.2 什么是软件

软件是一套完整交付的工具集合，用来解决一整套复杂场景需求，不只有代码。一套软件通常包含：

1. 多个可执行程序（核心功能）；
2. 配套资源：图片、配置文件、字体、插件、依赖库；
3. 辅助内容：说明文档、安装向导、卸载工具、许可证。

一个软件通常由很多个程序组成。

#### 5.3 什么是进程

进程是运行中的程序，是操作系统进行资源分配和调度的基本单位，是动态的。当你双击运行可执行文件、打开软件时，程序被加载到内存中，由 CPU 调度执行，就成为了一个进程。

- 一个程序可以对应多个进程：比如打开两个浏览器窗口，就是同一个浏览器程序启动了两个独立进程；
- 进程有生命周期：从启动运行到执行结束退出，会持续占用 CPU、内存等硬件资源；
- 进程之间相互独立：一个进程崩溃，通常不会影响其他进程运行。

#### 5.4 实验场景中的进程管理

理解进程是后续实验调试、排错的基础，常见的应用场景：

1. **程序卡死处理**：实验程序运行异常、无响应时，可以通过进程管理工具强制结束进程，无需重启电脑；
2. **资源监控**：运行大数据、AI 模型等重负载实验时，可以通过进程查看 CPU、内存占用，判断程序是否正常运行；
3. **残留进程清理**：程序异常退出后，可能残留后台进程占用资源，需要手动结束。

#### 5.5 基础进程查看方式

- **Windows**：按下 `Ctrl + Shift + Esc` 打开任务管理器，可查看所有进程、结束进程；
- **macOS**：聚焦搜索打开“活动监视器”，或终端使用 `ps` 查看进程、`kill` 结束进程；
- **Linux**：终端使用 `ps`、`top` 查看进程，`kill` 结束进程，后续章节会详细讲解。

## 二、文件

### 1. 文件、目录和扩展名

#### 1.1 文件

文件是操作系统存储数据的基本单元。一段文字、一行代码、一张图片、一份实验数据，所有内容都会以文件的形式保存在硬盘里。文件本质是二进制数据的集合，操作系统通过统一的文件接口完成硬件数据读写；每个文件都有专属名称作为唯一标识，且必须存放在目录内，无法脱离目录独立存在。

#### 1.2 目录

目录是操作系统分类存放文件与子目录的容器，文件通过目录实现分层有序管理。目录本质是记录文件存放位置的集合，操作系统依靠目录把所有文件整理成清晰的树形结构；每个目录都有专属名字用来区分归类，只能嵌套在其他目录中，不能脱离存储层级单独存在。不同操作系统的目录可能有略微差异，具体区别如下：

- **Windows**：分多根，每个盘符为一根，如 `C:\`、`D:\`；
- **macOS / Linux**：单一根 `/`，无盘符，所有目录都挂载在根目录下。

#### 1.3 扩展名

文件名由两部分组成：`主文件名.扩展名`，中间的 `.` 作为分隔符。扩展名用来标记文件类型，告诉操作系统用什么软件打开、识别代码格式。常见的扩展名如下：

| `.txt` | 纯文本文件 |

### 2. 路径

路径是定位文件的完整“地址”，命令行、代码读取文件时必须通过路径找到目标，分为绝对路径、相对路径两类。

#### 2.1 绝对路径

绝对路径是从根目录开始写完整地址，无论当前在哪一级目录，输入路径都能精准定位文件。

- Windows 示例：`D:\lab\exp1\hello.c`
- macOS 示例：`/Users/utlab/lab/exp1/hello.c`
- Linux 示例：`/home/utlab/lab/exp1/hello.c`

#### 2.2 相对路径

相对路径不写完整的根目录地址，以当前所在目录为起点定位文件，在命令行操作中较为常用。在使用相对路径时，需要使用一些特殊路径的标记以用来简化输入。

假设路径结构如下，当前处于 `~/lab` 文件夹下：

```text
用户目录 ~
└── lab
    ├── report.pdf
    └── exp1
        └── hello.c
```

| 符号 | 含义 | 使用示例 | 访问 |
| --- | --- | --- | --- |
| `.` | 当前目录 | `./hello.c` | `hello.c` |
| `..` | 上一级父目录 | `../report.pdf` | `lab` 下的 `report.pdf` |
| `~` | 当前用户目录 | `~/lab` | 直接跳转个人目录 `lab` 文件夹 |

#### 2.3 注意事项

1. 不同系统的路径分隔符不一致，必须注意，不允许混用正反斜杠。Windows 系统中使用反斜杠 `\`，例如 `D:\lab\exp1`；而在 macOS 与 Linux 中使用的是正斜杠 `/`，例如 `/Users/utlab/lab/exp1`。
2. 路径中禁止中文路径，禁止路径和命名文件夹时带空格，禁止使用特殊符号，学会使用下划线 `_` 命名文件。
